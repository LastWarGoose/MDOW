# AGENTS.md

## Цель и границы MVP

Создай локальное настольное приложение: ссылка YouTube → разрешённая загрузка аудио → MP3 → редактирование тегов → сохранение. Целевая платформа MVP — Windows; интерфейс на русском. Один ролик за операцию, без плейлистов, трансляций, аккаунтов и сервера. Предусмотри импорт законно полученного локального аудиофайла.

## Стек и архитектура

- Python 3.12+, PySide6 для интерфейса, yt-dlp для разрешённого извлечения, FFmpeg/ffprobe для конвертации и проверки, Mutagen для ID3, Pillow для обложек. Фиксируй проверенные версии зависимостей и внешних инструментов; документируй установку.
- Раздели `src/app/` на `ui/`, `services/`, `adapters/`, `models/`; тесты храни в `tests/`. UI вызывает сервисы, сервисы работают через заменяемые адаптеры загрузчика, конвертера и тегов.
- Сеть и обработку выполняй вне потока UI; внешние процессы должны поддерживать отмену. Обновляй UI через сигналы Qt. Состояния задачи: проверка, загрузка, конвертация, редактирование, сохранение, завершение, ошибка, отмена.
- Показывай этап и доступный прогресс, понятные ошибки и кнопку отмены. Редактор доступен сразу после получения метаданных; пользовательские изменения сохраняются при завершении загрузки. Не выдумывай исполнителя и альбом из названия канала.

## MP3 и ID3

- Загружай только аудиопоток. Конвертируй в MP3 через `libmp3lame`, по умолчанию VBR `-q:a 2`; не обещай улучшения исходного качества.
- Записывай ID3v2.3 с Unicode/UTF-16: название — `TIT2`, исполнитель — `TPE1`, альбом — `TALB`, обложка — `APIC` (front cover), несинхронизированный текст песни — `USLT`. Используй полный API Mutagen. См. [документацию ID3](https://mutagen.readthedocs.io/en/latest/user/id3.html).
- Разреши менять и удалять все пять полей; не создавай дубликаты обложек и текста. Сохраняй остальные совместимые теги. Обложку проверяй и преобразуй в JPEG/PNG, максимум 1500×1500 пикселей и 2 МБ после обработки. Текст песни вводится пользователем.
- При изменении тегов не перекодируй аудио. Сохраняй через временную копию в каталоге назначения, проверку и атомарную замену; чужой существующий файл не перезаписывай без подтверждения.

## Безопасность и правомерное использование

- До загрузки показывай условия использования и запрашивай подтверждение законного основания. Само подтверждение, публичная доступность или лицензия ролика не гарантируют разрешения выбранного способа скачивания: учитывай применимое право и [условия YouTube](https://www.youtube.com/static?template=terms). При неясном основании предлагай импорт законно полученного файла.
- Не реализуй обход DRM, платного доступа, авторизации, региональных и иных ограничений. Не импортируй cookies браузера. Ошибки ограничения доступа завершают задачу; не обходи их повторными попытками. Проверяй лицензии распространяемых библиотек и сборки FFmpeg.
- Принимай только HTTPS-ссылки с явно разрешёнными именами хостов YouTube и `youtu.be`; разбирай URL библиотекой, извлекай ID и создавай канонический URL. Запрети произвольные адреса, локальные пути и generic extractor. Сетевые обращения адаптеров не должны достигать loopback, частных и служебных адресов, включая перенаправления.
- Запускай процессы списком аргументов без shell; запрещай пользовательские параметры команд. Изолируй временные каталоги, очищай имена файлов и проверяй итоговые пути. Недоверенные названия, теги и тексты отображай как обычный текст.
- Ограничь длительность ролика (2 часа), загрузку (500 МБ), исходную обложку (10 МБ и 25 мегапикселей), текст песни (100 тысяч символов); контролируй лимиты во время обработки. Настрой тайм-ауты и проверку свободного места. Не логируй секреты, подписанные URL и содержимое пользовательских файлов.

## Оптимизация и надёжность

- Для MVP выполняй одну тяжёлую задачу одновременно; читай и пиши потоково, не загружай аудио целиком в память. Не скачивай видео. Повторные изменения тегов используют готовый MP3.
- Не более трёх попыток только при временных сетевых ошибках, с увеличением задержки и учётом `Retry-After`. Отмена останавливает дочерние процессы и очищает частичные файлы; после аварийного завершения убирай только собственные устаревшие временные данные.
- Проверяй наличие FFmpeg/ffprobe при запуске. Изменения YouTube локализуй в адаптере yt-dlp; обновляй его после проверки совместимости, без самовольного обновления установленного приложения. См. [требования yt-dlp](https://github.com/yt-dlp/yt-dlp#dependencies).

## Тестирование

- Используй pytest, pytest-qt и Ruff. Unit-тесты: URL и пути, лимиты, переходы состояний, замена/удаление тегов, кириллица, многострочный текст, повреждённая обложка.
- Интеграционные тесты на локальных лицензированных или синтетических образцах: конвертация с проверкой ffprobe, повторное чтение всех тегов Mutagen, неизменность аудиопакетов после редактирования тегов.
- Проверь сетевые ошибки через подмену адаптера, отмену на каждом длительном этапе, отсутствие FFmpeg, нехватку места, отказ записи и конфликт имён. Исходный файл должен сохраняться при неудачной записи.
- CI работает без YouTube и проверяет форматирование, линт и тесты. Отдельный ручной smoke-тест разрешённой загрузки выполняй перед выпуском; воспроизведение MP3 и отображение тегов проверь в двух целевых проигрывателях.

## Критерии готовности и работа Codex

- Полный сценарий от разрешённой ссылки до воспроизводимого MP3 работает; все пять полей сохраняются и правильно читаются после повторного открытия, включая кириллицу, замену и удаление обложки и текста.
- Интерфейс остаётся отзывчивым; отмена завершает процессы и освобождает файлы. Ошибки понятны пользователю, частичные результаты не выдаются за готовые, исходные файлы не повреждаются.
- Проверки проходят: `ruff check .`, `ruff format --check .`, `pytest`. README содержит установку, запуск, ограничения, проверенные версии инструментов и порядок сборки; собранное приложение проверено на чистой Windows.
- Вноси небольшие изменения по задаче, не добавляй сервер и лишние зависимости. Перед завершением сообщай, что изменено, какие проверки реально выполнены и какие ограничения остались; не называй невыполненные проверки успешными.
